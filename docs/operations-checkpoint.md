# Sled, Wasmtime, and gameplay checkpoint

This checkpoint preserves the database and scripting replacements and the completed gameplay additions. It does **not** establish full pre-renewal game coverage. The remaining work below is the handoff for the next implementation session.

## Included work

- Persistent accounts, characters, inventories, skills, variables, bonuses, and supported world systems use Sled. PostgreSQL and SQLx are removed from the Rust dependency graph. A fresh database is seeded from repository assets; existing PostgreSQL data is not migrated.
- Inventory consumption, grants, resource changes, persistent script variables, world changes, and shared reward-pool receipts use multi-key/multi-tree transactions. Application code makes no explicit database flush calls.
- Wasmtime executes compiled Rust NPC, item, pet, and event code. The SDK, offline import tools, guest sources, manifests, and compiled bundle are included. An rAthena checkout is an offline reference/import input, not a runtime VM dependency.
- Item targeting and dialogs defer their source transaction until completion and reject replaced sources, insufficient resources, and applicable late map restrictions. Native Teleport pays when its menu opens and preserves the current instance for random teleport.
- Combat additions cover equipment/card effects, conditional weapon bonuses, skill resistance, Misc defense, signed elemental absorption, critical/mastery/refine ordering, incoming shields, reflection, procs, and actual monster classes. Passive range and ASPD rates are carried through calculation and client skill displays.
- Existing damaging hit packets now carry notification metadata through the damage queue and emit resolved damage/healing after admission. Player, monster, NPC, companion, ground, delayed, splash, and reflected hit paths use the common packet builder. Blocked hits report zero, amounts respect HP capacity, dual-hand shares follow the resolved total, and Devotion redirects keep one displayed result on the original target. Captured map/instance scope rejects hits delivered after a recipient changes maps. Normal damage packets use the client's legacy 16-bit, 2007 32-bit, or 2013 SP-aware format; larger normal hits no longer truncate to a legacy damage field on newer clients. Cast/support effects and Palm Strike's pre-hit animation remain separate notifications.
- Supported status, offensive, support, ground, delayed, and area skills use the existing game/map loops. Scripted unit casts carry actual source IDs, cast-time adjustments, cancellation overrides, monster messages, targeting/ground options, and source snapshots. See the casting limitations below.
- Classic hunter ground effects now cover Skid Trap, Ankle Snare, Land Mine, Shockwave, Sandman, Flasher, Freezing Trap, Blast Mine, and Claymore Trap. Player casts share the actor ground code. Ankle Snare links its hold to the specific trap, uses the classic AGI/boss/caster-level duration, and releases only that hold on removal or expiry. Delayed capture/effect requests check their map scope; cancellation invalidates pending captures. Misc trap formulas preserve signed elemental absorption. Remove Trap validates ownership/range and recovers one unused trap through the inventory transaction; Spring Trap requires a falcon, spends a trap without refund, and preserves an active capture. Unused player traps recover as floor items at expiry, except Blast Mine, which expires as a spent trap. Ground units retain the existing placement/cast-payment flow and versioned entry/look/deletion packets.
- Trap units have 3,500 durability, a distinct actor type and map-scoped targeting snapshots. Normal attacks and skills marked `TargetTrap` resolve through the game loop; spent traps reject new damaging targets. Destruction releases linked captures and does not return a recovery item. Skill knockback moves eligible trap units while honoring `NoKnockback`; Ankle Snare stays fixed. Claymore affects neighboring trap units and marks the classic supported types as spent, without inventing secondary explosions. Native area damage now includes eligible players/companions and trap units, and Bowling Bash collision processing includes those recipients. Supported scripted actor and mercenary Arrow Shower paths can target trap units. Ground-unit appearance is refreshed when an authenticated character approaches or reconnects, with session identity tracked through weak references.
- `game.skill_units` configures the trap damage-source mask using `MapActorType`, versus-map trap targets, and inventory-full recovery drops. Defaults match the classic reference: only players damage durability, player traps can hit allies and the caster on versus maps, and failed recovery grants do not drop a floor item. Recovery grants now enforce inventory weight/slot/stack capacity in the Sled transaction; capacity failures send the pickup failure result and remove the trap, while storage/conflict errors preserve it. Enable `drop_recovery_items_when_full` for the floor-item fallback.
- Talkie Box accepts versioned, session-bound text input, preserves the client's message bytes, and creates a non-damaging trap. Any living, loaded player except the caster can trigger it; it broadcasts once, changes to the used-trap appearance, and expires five seconds later. NPC and other non-player casts use the reference's default message. Unused player Talkie Boxes follow normal trap recovery, while triggered or sprung boxes do not refund materials.
- Graffiti shares the versioned text input and displays its message with the dedicated ground-entry packet, including visibility refresh after approach or reconnect. Player casts enforce one active Graffiti per map instance before payment; non-player casts retain the reference's placement rules and default message. Graffiti expires after its configured classic duration and follows caster cleanup. Scribble removal (`RG_CLEANER`) clears Graffiti within the skill's square splash area through the ground-unit lifecycle. Player, item-issued, and scripted actor ground paths are connected; deferred player cleanup rechecks map, status, and terrain before payment.
- Trap placement honors each skill's `NoFootSet` and `NoReiteration` flags and the actor masks in `game.skill_units.nofootset_sources` and `reiteration_sources`. Defaults enforce occupancy checks for player casts and allow no reiteration overrides. Monsters retain the reference's additional monster-occupancy check. Cast completion revalidates placement before deferred payment; pending groups do not block earlier completed casts. Warp Portal shares these placement checks and retains its overlap and group-count rules. Optional `multi_trigger_traps` restores one effect per eligible actor in a single scan. Optional `return_all_trap_materials` makes Remove Trap return every deployment item through one inventory transaction; capacity failure can drop the full amounts when the configured fallback is enabled. Both options default to false.
- Supported party, guild membership/storage, cart, personal storage, vending, buying-store/search, fame, homunculus, mercenary, and pet operations have persistence and event handling. These are partial implementations of their larger game systems.
- Cart transfers enforce `NoUseCart`; vending and buying-store preparation/creation enforce their current map flags. Map movement closes storage and stale shop windows, atomically relocates active shop listings, and closes each shop prohibited on the destination. Failed relocation restores the character to its source map. These checks use runtime instance flags, including changes made after preparation.
- Demon Shock, Estin, Estun, and Esma have execution paths for player, monster/NPC, and scripted companion casts using classic metadata. Demon Shock converts eligible subsequent normal attacks to magic for its duration. Estun stuns medium targets; level-seven Estin/Estun enables Esma, whose readiness is consumed on completion. Player SP costs include Kaina's level-dependent reduction. The default `game.allow_es_magic_players: false` rejects non-monster Es targets with the classic caster stun and failure response. Damage uses the existing signed elemental, reflection, map-rate, and notification machinery.
- Pet capture and loot use map reservations with transaction-backed completion or rollback. Cargo retains item identity, cards, refine, and damage state. Overflow remains hidden until committed, respects `NoDrop`, and can complete after logout. Pet support/combat and owner experience are configurable.
- Pet automatic bonuses support attack, incoming-hit, and owner-skill triggers through `petautobonus`, `petautobonus2`, and `petautobonus3`. Nested bonus/visual scripts compile into a pet program catalog. Repeated triggers refresh the timer, bonus programs participate in status recalculation, and active bonuses are tied to the source pet's identity and removed when that pet is returned or lost. The stock pet assets define no automatic bonus programs; pet overrides can supply them without changing the runtime.
- Pre-renewal map rules are imported into the repository. Working consumers include player hostility, party/guild protection flags, siege-dependent castle hostility, GvG/BG damage rates, experience/drop restrictions, item-use/branch/teleport/return restrictions, capture/drop rules, and client map properties. Party warps preserve explicit party IDs, source-map filters, scatter radii, and destination instances.
- `SkillDamage` adjusts admitted skill damage for players, monsters, NPCs, homunculi, and mercenaries. Queued attacks retain the actual caster type, including pets and summons; recipient groups distinguish players, normal monsters, boss monsters, and other actors. Map-wide, per-skill, and imported skill-damage database rates combine with signed integer arithmetic. Redirected damage retains its adjustment marker, and right-hand drain/proc shares follow admitted damage. The database importer supports classic skills and map/zone selectors; the stock adjustment catalog is empty.
- `SkillDuration` scales the lifetime of implemented ground units and traps, using the reference's integer division order and supporting zero duration. Existing units retain their placement-time lifetime when flags change. Meteor scheduling keeps its explicit lifetime rather than increasing the number of meteors. Additional ground-skill handlers remain incomplete, including the classic hunter traps listed below.
- `NoSave` redirects persisted/relogin locations to the configured alternate location or the character's save point. Deferred position writes and full saves carry monotonic revisions, so an older movement write cannot overwrite logout/shutdown state. NPC scripts support `setmapflagnosave`, `savepoint`/`save` with optional ranges/target characters, and `getsavepoint`; save-point changes commit atomically before changing live state.
- `/memo` stores up to three locations, moves the newest location to the front, replaces duplicate maps, and enforces Warp Portal skill level, `NoMemo`, `NoWarpTo`, and instance restrictions. Memo records use Sled game-system transactions and survive reconnects.
- Warp Portal uses the save point and the memo destinations allowed by the requested skill level. SP/source consumption commits at the end of casting; fresh gemstone requirements commit only after a valid destination choice. Portals open after two seconds, expire five to twenty seconds after creation, and carry seven to ten uses. Placement, overlap, three-portal limits, source/choice login bindings, entry deduplication, and menu cleanup are implemented. Player portals survive their caster's map change/death and end with logout; NPC portals use the compiled `warpportal` command and retain NPC identity/instance scope. Destination selection blocks player actions until selection, cancellation, death, map change, or timeout.
- The death menu's return-to-save-point action respawns the character instead of logging out. Normal respawns and dead-character saves use classic restart HP/SP, the novice HP minimum, and full-recovery equipment. Optional `game.restart_hp_rate` and `game.restart_sp_rate` default to zero; SP is preserved above the configured minimum. Dead-character relogin goes to the save point with restored pools. Battleground-specific respawns and jail/instance reconnect policy remain incomplete.
- Ordinary player trading supports authenticated client request/accept/offer/lock/confirm/cancel flows, virtual offers, two-sided atomic completion, stable inventory refresh, and cancellation on idle timeout, death, disconnect, map change, or changed conditions. Session IDs survive restarts and receipts bind replays to the original offer payload.
- Pet-egg custody follows account/guild storage, cart, vending, and ordinary trading transfers. Equipment and wallet changes commit before live updates; stale generic character saves and deferred equipment writes cannot overwrite a completed trade. Inventory loading and seeding preserve distinct crafted/split stacks.
- NPCs have canonical combat state and map-owned damage, healing, status effects, expiry, movement, cast interruption, and reflection. NPC unit-data reads/writes cover all 46 NPC fields and reply after the owning map applies the request. Transfers preserve script metadata and instance variable scope, with rollback when installation fails.
- Registered compiled NPC handlers support `OnInit`, `OnInstanceInit`, `getnpcid`, `doevent`, and `donpcevent`. Attached events wait for the current conversation; background events run without a player and can use NPC/server variables, unit commands, map flags, spawning, and announcements. Named monster callbacks retain the receiving NPC's identity and variable scope.
- NPC timers support `initnpctimer`, `startnpctimer`, `stopnpctimer`, `setnpctimer`, `getnpctimer`, `attachnpctimer`, and `detachnpctimer` for registered compiled `OnTimer<ticks>` handlers. Player countdowns support `addtimer`, `deltimer`, and signed `addtimercount` adjustments. Timers use the game loop, retain instance scope through NPC transfers, bind attached callbacks to the original login session, and cancel queued callbacks on reset, stop, countdown deletion, or logout.
- Registered `OnTimerQuit` handlers run with retained player data before logout saves/removes the character. Quit callbacks can read the canceled timer's tick, use persistent and NPC variables, and perform supported host operations. Display-only client commands are ignored; waiting for client input is rejected. Callback requests and queued changes carry a token that expires when cleanup ends. Return to character selection, explicit disconnect, and map-socket EOF feed the game-loop logout path; later character selection waits for cleanup before reading persisted data.
- Character admission and map entry install state on the game loop. Selection messages carry fresh, transferable data rather than active skill objects. Map startup is queued after the client acknowledgement, stale admission requests are rejected, and repeated selection during bootstrap does not replace the selected character. Failed character-server authentication no longer replaces the account's session or re-enters its session lock.

## Build and validation

Run from the repository root with the project's nightly Rust toolchain. Integration tests use temporary Sled databases and require no database service.

```powershell
cargo build --workspace --release
cargo test --workspace --release --features unit_tests
cargo test --package server --bin server --release --features integration_tests
python -m unittest discover -s tools/scripts-import -p test_mapflags.py
cargo run --package tools --bin scripts-build --release
```

For a fresh local run, copy `config.template.json` to the ignored `config.json`, then run `cargo run --package server --bin server --release`. The configured database directory and build outputs are ignored. Include `config/wasm/`, `scripts/` sources and lockfile, both new script crates, import/build tooling, and the new server files in the commit.

## Generic monster attack skills

A probe over all 5,494 imported mob skill entries showed that most `NPC_*` attacks were rejected by `validate_script_actor_operation`. Now accepted for monsters and NPC actors:
- Weapon-type `NPC_*` skills (element attacks, combo, critical slash, guided, stun/poison/curse/etc. attacks, splash attack, Pulse Strike, Hell Judgement, bleeding/armor/shield breaks): physical damage at 100% per hit, the metadata element (`Weapon`/`Random` resolved by `BattleService`), hit count from metadata, no flee roll for `IgnoreFlee`/Critical Slash. `IgnoreDefense` is not honoured. Splash radius comes from the metadata.
- Magic-type `NPC_*` skills with a target (Dark Strike, Dark Thunder, Energy Drain...): MATK at 100% per hit via `metadata_magic_damage`.
- `NoDamage` self/target statuses whose metadata status exists in `StatusChangeKind` (Defender/Armor, Invisible, Stop, Invincible...).
- Wide area statuses: `NPC_WIDESLEEP/STONE/FREEZE/STUN`, plus `NPC_WIDESOULDRAIN` (previously mis-rejected).
- Mob skill levels above the player maximum (for example Magnum Break level 25) are clamped to the metadata maximum instead of dropping the entry.

Still rejected (checked with the probe): Meteor Storm, Vermilion, Storm Gust, Fire Wall, Earthquake, Grand Cross lifecycles; Water Ball, Intimidate, Vampire Gift callbacks; Safety Wall, Sanctuary, Reflect Shield, Venom Dust, Body Relocation, Reverse Orcish; Power Up/Agility Up and other monster-only statuses with no `StatusChangeKind`; Self Destruction, Dark Breath, Grand Darkness, All Heal, Metamorphosis, Summon Monster, Change-element skills, Run/Talk/Keeping/Emotion-On.

Actor ground lifecycles added: Fire Wall, Storm Gust and Vermilion use the generic actor magic-ground tick (`tick_actor_magic_ground`), and Meteor Storm is placed as one short-lived ground unit per meteor (`place_actor_meteors`, random centre within the splash radius, spaced by the metadata interval). Not reproduced for actors: Fire Wall's per-cell hit budget and knockback, Storm Gust's freeze rule and knockback, and the Storm Gust/Vermilion wave caps (duration limits them). Earthquake and Grand Cross still have no actor lifecycle.
